# Eigenrays

## What an eigenray is

A source radiates rays in every direction. Only a few of them pass through any particular point. Those few are the **eigenrays** for that source and that point: the distinct routes by which sound actually gets from one to the other.

In open, uniform water there are three obvious ones: straight across, by way of the surface, and by way of the bottom. In a real ocean there may be a dozen, each bending through the profile differently and touching the boundaries a different number of times.

::play

Each eigenray is a complete description of one path. It answers four questions:

- At what angle did it **leave**?
- At what angle did it **arrive**?
- How **long** did it take?
- How much did it **lose**?

:::try
Drag the amber field point around the water. Paths appear and vanish as you cross boundaries between regions. Switch the environment to the surface duct and put the field point just below the layer at long range: the table goes empty. That is a shadow zone, seen from the inside.
:::

:::key
Transmission loss is a summary. Eigenrays are the detail it was summed from. Active sonar needs the detail, because beams, reverberation and target strength all depend on angle and time, path by path.
:::

## The eigenray table

An engine reports eigenrays as a table, one row per path. The columns vary by engine but always include these:

| Column | Meaning | Used for |
|---|---|---|
| Launch D/E | Direction leaving the source | Transmit beam pattern |
| Arrival D/E | Direction at the field point | Receive beam pattern, target strength, scattering |
| Travel time | Seconds from source to point | Echo timing, time spread |
| Loss or amplitude | This path’s loss alone | The loss sum |
| Phase | Phase shift along the path | Coherent sums |
| Surface bounces | Count | Surface loss, path naming |
| Bottom bounces | Count | Bottom loss, path naming |
| Turning points | Upper and lower | Path naming |

The total loss to the point is the sum over the rows: a power sum for incoherent loss, or a sum of complex pressures for coherent loss.

:::pipeline
An eigenray product is ragged. The number of rows changes from cell to cell, from zero in a shadow to dozens in shallow water. Storing it needs a variable-length layout or a fixed maximum with a count. Either way it is far larger than the loss field, and many pipelines keep it only inside the engine stage.
:::

## Path families

Paths are named by what they touch. The names are shorthand you will hear constantly.

- **Direct path.** No boundary, no turning point. Short range only, since refraction soon bends it away.
- **Surface reflected.** One or more surface bounces.
- **Surface duct.** Refracts upward, reflects from the surface, repeats. Stays in the mixed layer.
- **Bottom bounce.** One or more bottom reflections. Steep angles, intermediate ranges.
- **Refracted, refracted.** Turns at depth and near the surface without touching either boundary. The cleanest long-range path.
- **Refracted, surface reflected.** Turns at depth and reflects from the surface. Convergence zone paths in most oceans are of this kind.

Engines often group rays into such families and report one representative eigenray per family, averaging over the bundle. GRAB works this way: test rays with the same count of boundary hits and turning points form a family.

:::operator
Knowing the family tells you what the path is sensitive to. A bottom-bounce detection depends on the bottom. A duct detection depends on the layer and the sea state. A convergence zone detection depends on the deep profile and on there being depth excess.
:::

# Angle carries meaning

## Launch angle and the transmit beam

A source rarely radiates equally in all vertical directions. It has a **transmit beam pattern**: full level in the direction it is steered, less elsewhere.

Each eigenray leaves at its own launch D/E, so each one is weighted by the pattern at that angle. A path that leaves 20° off the beam’s axis starts out many decibels down before the ocean has done anything to it.

This is why loss depends on the sensor and not only on the ocean. The same water gives a different effective loss field for a source with a narrow beam steered horizontally than for one that radiates in all directions.

:::try
In the eigenray explorer, steer the receive beam down by 15° and narrow it to 10°. The faint bars in the arrival plot are the paths as the ocean delivers them. The solid bars are what the beam lets through. By reciprocity the same picture describes a transmit beam.
:::

:::pipeline
There are two ways to apply a beam pattern. The engine can weight rays at launch and return a loss field with the beam already inside it. Or the engine can return eigenrays for an omnidirectional source and the pattern is applied afterward. The second is more flexible and needs the eigenrays kept. Know which your loss fields are, or the pattern gets applied twice or not at all.
:::

## Arrival angle and the receive beam

The same weighting happens at the receiver. The array listens through beams, each steered to a D/E and each with a width. An arriving path is accepted or rejected according to its arrival angle.

For an active sonar the two-way path multiplies the possibilities. Sound can go **out** by any eigenray and come **back** by any eigenray. With four paths each way there are sixteen combinations, each with its own:

- total travel time, the outbound time plus the return time
- total loss, with the transmit pattern applied at the launch angle and the receive pattern at the arrival angle
- angle at the target

Engines differ in how they reduce those combinations to one echo level. Some sum the power of all combinations that arrive within the same time window. Some take the strongest. CASS, for example, forms the signal from the combinations of outbound and return eigenrays at each range and selects the peak signal-to-masking level.

:::key
An echo is not one path. It is every combination of a way out and a way back that the beams accept and that arrive close enough in time for the processor to treat as one.
:::

## D/E at the target

The target does not know how far away the sonar is. It responds to the direction the sound arrives from and the direction it leaves in.

The vertical part of those directions is the D/E of the path at the target. For a distant target on a duct path this is within a degree or two of horizontal, and the usual target strength table applies. For a bottom-bounce path it can be 20° or 30° from below. For a sensor almost directly above the target it approaches 90°.

Target strength changes with that angle. A feature that reflects strongly when struck from the side may reflect weakly from below.

:::pipeline
A full target strength lookup takes aspect in the horizontal, D/E in the vertical, and frequency. If the engine reports only total loss, the D/E at the target has been thrown away and the lookup falls back to a horizontal value. That is reasonable for duct and direct paths and not for steep ones.
:::

## Grazing angles and reverberation

The same angles drive reverberation. Sound that strikes the seabed scatters some energy back, and how much depends strongly on the **grazing angle** at which it strikes and the angle at which it leaves.

So a reverberation model needs, for every patch of bottom and surface, the paths from the source to that patch and from the patch to the receiver, with their grazing angles. That is the eigenray problem again, with the boundary as the field point.

Two consequences:

- Reverberation prediction costs much more than loss prediction, because it needs paths to every scattering patch in both directions.
- Reverberation is very sensitive to the vertical beams. A beam that keeps energy off the bottom lowers bottom reverberation directly.

:::operator
When bottom reverberation is the limit, the useful question is which paths are putting sound on the bottom at steep angles, and whether a different sensor depth or beam steer would take them away.
:::

# Time carries meaning

## Multipath time spread

Paths of different length arrive at different times. A pulse sent as one clean burst arrives as several overlapping copies. The interval between the first and the last is the **time spread**.

In deep water over a direct path the spread is milliseconds. In shallow water with many bottom bounces it can be a large fraction of a second. For an echo, the spread of the outbound paths and of the return paths combine.

Time spread has three effects on an active sonar:

- The echo is **longer** than the transmitted pulse, and its energy is divided among more range cells.
- A processor that expects the energy in one cell loses some of it. This is a time-spread loss, a few decibels when the spread exceeds the processor’s resolution.
- Range accuracy is limited by the spread, however fine the waveform’s resolution.

:::key
A waveform can resolve two meters. The ocean may not let it. When multipath spread is larger than the resolution cell, a finer waveform buys less reverberation and no better echo.
:::

## Which path gave the range

A sonar turns echo time into range by assuming a path and a speed. Usually the assumption is a straight line at a nominal sound speed. That is fine for direct and duct paths.

For other paths it is biased. A bottom-bounce echo has gone down to the seabed and back up on each leg. Its path is longer than the horizontal distance, so a straight-line conversion reports a range that is too great. A convergence zone echo travels a long deep arc at speeds higher than the surface value, and the error can go either way.

Correcting the bias needs the travel time of the actual path, which is in the eigenray table.

:::pipeline
The same mapping is needed in reverse when measured data enters a prediction. Measured reverberation arrives as level against **time**. To set it beside modeled signal excess against **range**, each time must be converted to range with the same path assumption the prediction used. Use two different assumptions and the curves slide past each other.
:::

## Paths, beams and what the operator sees

Put the last three branches together and one target can produce a surprising display.

- It can appear on more than one vertical beam at once, because different paths arrive at different D/E.
- It can appear at more than one range, because different path combinations have different total times.
- Its level can jump as it crosses from a region served by one path family into a region served by another.

None of this is a fault. It is the arrival structure showing through. A prediction that carries eigenrays can say which of these to expect. One that carries only loss cannot.

:::operator
A contact that is strong on a depressed beam and absent on the horizontal one is telling you its path: bottom bounce. That in turn tells you the range is somewhat less than the display says.
:::
