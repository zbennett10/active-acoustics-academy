# Stages

## Inputs

A prediction is only as good as what goes into it. There are three kinds of input, and they come from different owners.

**The environment**, by position:

- Sound speed profiles, from climatology, an ocean forecast or an in situ drop.
- Bathymetry, from a gridded database.
- Bottom type, as acoustic provinces that map to loss and scattering parameters.
- Wind speed, for surface loss, surface scattering and wind noise.
- Shipping density, for low-frequency ambient noise.

**The sensor and its processors:**

- Position, depth, heading.
- Array geometry or beam patterns, transmit and receive.
- For each processor: band, waveform, source level, detection threshold or recognition differential.

**The target:**

- Depth, or a set of depths to consider.
- Target strength table, and an assumed aspect.
- Speed, if any processor depends on Doppler.

:::key
Environment describes the world. Sensor and processor describe the system. Target describes an assumption. Keep the three apart in the data model, because they change at different rates and for different reasons.
:::

## The engine run

The propagation engine turns environment and sensor geometry into loss. One run has a definite shape.

- It is centered on **one sensor position and depth**.
- It is for **one frequency or band**.
- It covers a set of **bearing radials**, each a vertical slice of ocean from the sensor outward.
- Along each radial it fills a grid of **range by depth**.

For each radial the engine samples the environment along that line, picking up changing profiles and bathymetry as range increases. This is the N by 2D approach from unit 3.

A ray engine produces eigenrays first and loss second. A parabolic equation engine produces the pressure field directly. Either way the standard product is **one-way transmission loss** on a polar grid in three dimensions: bearing, range, depth.

Reverberation, when it is modeled, comes from the same run or a closely related one, since it needs the paths to the boundaries with their angles.

:::pipeline
Engine runs are the expensive step, seconds to minutes each. Everything after is arithmetic on arrays. A well-built pipeline computes loss as rarely as possible and recomputes the cheap stages freely.
:::

## From loss to signal excess

The stage after the engine combines loss with everything else. It does no physics of propagation. It applies the sonar equation at every cell.

For each sensor, each processor and each target description:

1. **Echo level.** $SL - TL_{out} - TL_{back} + TS$. Monostatic uses one loss field twice. Bistatic uses two.
2. **Noise.** Modeled band level less directivity index, or measured beam noise mapped to bearing.
3. **Reverberation.** Modeled level against range, or measured level against time converted to range.
4. **Masking.** Power sum of noise and reverberation.
5. **Signal excess.** Echo level less masking less detection threshold.
6. **Probability.** $\Phi(SE/\sigma)$.

::play

:::try
Select each box in turn and read its dimensions. Then move the range slider and watch the numbers ripple through: loss changes, so echo level changes, so signal excess changes. Noise does not move. Now change the bearing: with modeled noise, almost nothing changes.
:::

## Trace one cell

The surest way to understand or debug a pipeline is to follow a single cell from end to end by hand.

Pick a sensor, a processor, a bearing, a range and a target depth. Then collect, in order:

| Quantity | Example | Came from |
|---|---|---|
| Source level | 220 dB | Processor definition |
| One-way loss | 78.1 dB | Engine, this band, this radial |
| Target strength | 12 dB | Target table at assumed aspect |
| Echo level | 75.8 dB | Computed |
| Beam noise | 58.0 dB | Model, or measurement for the beam on this bearing |
| Reverberation | 48.7 dB | Model at this range, or measurement at this time |
| Masking | 58.5 dB | Power sum |
| Detection threshold | 10 dB | Processor definition |
| Signal excess | 7.3 dB | Computed |

If the displayed value at that cell is not 7.3 dB, the fault is between two rows, and the table shows which two.

:::pipeline
Build this trace into the system as a diagnostic: given a cell, return every term that went into it and where each came from. It turns a debate about whether a picture “looks right” into a check of nine numbers.
:::

# Shapes

## Dimensions of every product

Each product has a shape. Knowing the shapes is most of knowing the pipeline.

| Product | Dimensions | Notes |
|---|---|---|
| Environment | position, depth | Sampled along each radial |
| Transmission loss | sensor, band, bearing, range, depth | One way. The largest product kept |
| Eigenrays | as loss, plus path index | Ragged. Often not kept |
| Target strength | aspect, D/E, frequency | A lookup, not a field |
| Echo level | sensor, processor, target, bearing, range, depth | |
| Modeled noise | sensor, processor | A scalar if isotropic |
| Measured beam noise | sensor, processor, beam, time | |
| Modeled reverberation | sensor, processor, bearing, range | |
| Measured reverberation | sensor, processor, beam, time since ping | |
| Signal excess | sensor, processor, target, bearing, range, depth | |
| Probability | same as signal excess | |

Notice how the dimensions grow down the table. Loss depends on **band**. As soon as noise, reverberation and threshold enter, the product depends on **processor**. As soon as target strength enters, it depends on the **target** assumption.

:::key
Loss is per band. Signal excess is per processor and per target. Several processors in one band share one loss field and still have different signal excess.
:::

## Full-field and plan view are slices

A signal excess result for one sensor, processor and target description is a block with three axes: **bearing, range and depth**. The two standard displays are two ways of cutting it.

- A **full-field** fixes the **bearing** and shows range against depth. It answers: along this line, at what depths and ranges can I detect?
- A **plan view** fixes the **depth** and shows bearing against range, drawn as a map. It answers: for a target at this depth, where around me can I detect?

They share a line. The row of the full-field at the plan view’s depth is the same set of cells as the spoke of the plan view at the full-field’s bearing.

Look again at the two pictures at the bottom of the pipeline explorer. The dashed line in each marks where the other one cuts.

:::pipeline
Because they are slices of one block, the two displays must agree along the shared line. An automated test can check that: sample both along it and compare. A mismatch means the two views are not reading the same data, or are resampling it differently.
:::

## Grids, radials and resampling

The engine’s output is polar: evenly spaced in bearing and in range around the sensor. A map is rectangular in latitude and longitude. Getting from one to the other is **resampling**, and it is a source of quiet error.

Things to decide and to state:

- **Interpolation in what quantity.** Averaging decibels across a sharp edge gives a different answer than averaging power. Near a shadow boundary neither is true. Nearest-neighbor keeps edges sharp and looks blocky.
- **Angular resolution.** Cells widen with range. At 50 km, radials 5° apart are 4.4 km apart. Features narrower than that are missing, and interpolation draws a smooth bridge across the gap.
- **No data versus no energy.** A cell behind an island or below the seabed has no value. A cell in a shadow has a real, very low value. They must not be merged, and neither should be interpolated across.
- **Geodesy.** Bearing and range on a sphere are not straight lines on a flat map. Over tens of kilometers the difference shows.

:::pitfall
Smooth interpolation makes sparse data look confident. A plan view built from 8 radials and one built from 72 can look equally polished. Only one of them has seen the ocean between the spokes.
:::

## Units and conventions as metadata

Every array that crosses a boundary between services should carry enough description that the receiver cannot misread it. For acoustic products that means more than a unit string.

| Attribute | Example values |
|---|---|
| Quantity | transmission loss, signal excess |
| Reference | re 1 µPa, re 1 µPa²/Hz, re 1 m |
| One way or two way | one way |
| Sign | loss positive |
| Coherence | incoherent, band averaged |
| Band | center frequency and width |
| Range unit | meters, kiloyards, nautical miles |
| Depth datum | below mean sea level, positive down |
| Angle convention | D/E up positive, direction of look |
| Bearing reference | true, clockwise from north |
| Aspect convention | 0 at bow, clockwise |
| Receiver reference point | beam output, processor band |
| Provenance | modeled or measured, source, time |

Most of the pitfalls in this curriculum are one row of this table read wrongly.

:::pipeline
Conventions that are true for a whole system belong in its interface definition, stated once. Anything that can vary between products belongs on the product. The dangerous middle ground is a convention that everyone on the team simply knows.
:::

# Measured data and engineering

## Where measured data enters

Three measurements can improve a prediction, and they enter at three different stages.

**A measured sound speed profile** replaces part of the environment. It changes propagation, so the **engine must run again**. It is the most expensive update and it affects every downstream product.

**Measured beam noise** replaces the modeled noise term. It enters **after** the engine. No propagation is recomputed. Signal excess is updated by redoing a subtraction.

**Measured reverberation** replaces the modeled reverberation term, or the whole masking term. It also enters **after** the engine.

| Measurement | Replaces | Engine rerun | Cost |
|---|---|---|---|
| Sound speed profile | Environment input | Yes | High |
| Beam noise | Noise term | No | Trivial |
| Reverberation | Reverb or masking term | No | Trivial |

In the pipeline explorer, switch on measured beam noise and watch which boxes change and which do not.

:::key
Two of the three measurements are cheap to apply because they sit downstream of the engine. A pipeline that keeps loss separate from the sonar equation stage can absorb them in milliseconds.
:::

## Caching and invalidation

Since engine runs dominate cost, the engineering question is which inputs force a rerun and which do not.

| Change | Loss | Echo level | Signal excess |
|---|---|---|---|
| Sensor moves or changes depth | Recompute | Recompute | Recompute |
| Profile, bathymetry or bottom changes | Recompute | Recompute | Recompute |
| Processor band changes | Recompute | Recompute | Recompute |
| Target depth changes | Reuse, different slice | Recompute | Recompute |
| Target strength or aspect changes | Reuse | Recompute | Recompute |
| Source level changes | Reuse | Recompute | Recompute |
| Noise changes, modeled or measured | Reuse | Reuse | Recompute |
| Measured reverberation arrives | Reuse | Reuse | Recompute |
| Detection threshold changes | Reuse | Reuse | Recompute |

The loss field is keyed by sensor position and depth, band, and the version of the environment. Nothing else. A cache keyed that way survives most of what an operator does: changing target depth, aspect, processor settings and noise.

:::pipeline
Target depth deserves a second look. Loss was computed for all depths at once, so a new target depth is a different row of an array already in memory. A system that reruns the engine when the operator changes target depth is throwing away what it has.
:::

## Checks that catch plumbing errors

Physics offers free tests. Each of these catches a class of error with no reference data at all.

- **Spherical sanity.** In deep uniform water at short range, loss should be close to $20 \log r$. If it is $10 \log r$ or $40 \log r$, a factor of two has gone astray.
- **Loss is positive and mostly increasing.** A field with negative values or one that falls steadily with range has the wrong sign.
- **Reciprocity.** Loss from depth A to depth B equals loss from B to A.
- **Source level cancels in reverberation.** Raise it 10 dB: echo and reverberation both rise 10, noise does not move, and signal excess is unchanged wherever reverberation dominates.
- **Band scaling.** Double the bandwidth: modeled band noise rises 3 dB.
- **Power sum bounds.** Masking is never less than its larger term and never more than 3 dB above it for two terms.
- **Slice agreement.** Full-field and plan view match along their shared line.
- **Symmetry.** A flat, uniform ocean gives a circular plan view. If it is not circular, the bearing handling is wrong.
- **Sign flip of D/E.** Mirror the profile and the steer angle together: results should mirror.

:::operator
These same checks are useful to a reader with no access to the code. Change one input and predict what should happen to the picture. If something else happens, ask.
:::
